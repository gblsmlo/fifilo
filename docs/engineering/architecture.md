## Organizations

Authentication answers **who** is making the request. The active organization
and the membership answer **which tenant** the request may access.

- The server session is the source of truth for identity. `activeOrganizationId`
  alone does not authorize: the membership is re-validated on every protected
  request.
- Membership roles (`owner`, `admin`, `member`) are account authority. They are
  not business authorization; a product models its own policies on top.
- `allowUserToCreateOrganization` stays under the application's control so the
  creation of an organization is one transaction the app owns.
- Organization deletion is disabled by default. Owner-preservation hooks prevent
  removing or demoting the last owner. Invitations require a verified email and
  expire after 48 hours.
- Tenant-owned tables carry an `organization_id` and are reached only through
  the workspace transaction, which applies `set_config` inside the transaction.
  Auth tables (`users`, `sessions`, `accounts`, `verifications`, `two_factors`,
  `organizations`, `members`, `invitations`) are global and bypass it.

## Identifiers at the persistence boundary

Drizzle rows and projections keep ids as `string | null`, because that is what
the adapter delivers. The mapper is the boundary:

```text
Drizzle row (string) -> internal validation -> adapter mapper -> Core object (EntityId)
```

A cast to the semantic type is allowed only at a small, named point in the
adapter, for trusted persistence. Values from HTTP, queues, imports, cache or
raw SQL pass through Zod, `drizzle-zod` or a domain factory. `*Row` types
describe the technical representation; the repository return fulfills the Core
port. The id format is Decision 014.

## State in the browser

Server state lives in TanStack Query, form state in React Hook Form, URL state
in TanStack Router. Zustand holds only ephemeral UI state: an open panel, a
local preference, an unapplied filter. Remote data, cache, loading and mutations
are never duplicated in a store.

## Security baseline

- Session cookies are `HttpOnly`, `Secure` in production and `SameSite`.
- `BETTER_AUTH_TRUSTED_ORIGINS` lists exact origins per environment; a wildcard
  with credentials is never configured.
- Web and API share an origin by default; the browser reaches the API under
  `/api`, which the Vite dev server proxies.
- Authorization is enforced server-side. A client-supplied organization id, role
  or ownership claim is never authorization evidence.
- Schema changes generated by the CLI become versioned Drizzle migrations. Nothing
  migrates on startup.
- Logs redact tokens, secrets, passwords, cookies, sessions, credentials, OTP
  codes and keys by default. See [observability.md](observability.md).

## Copy-and-own UI

Primitives in `packages/ui` are copied into the repository and owned here. They
are not an opaque dependency and they are not copied again into features.
Updates are deliberate, recorded in `packages/ui/docs/UPDATE_WORKFLOW.md`, and
protected by the tests and stories that consume them.
